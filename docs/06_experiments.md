# Реестр экспериментов

## Как вести

- Каждый запуск оценки дописывает строку в `reports/runs.jsonl` (см. [01_spec_data_eval.md](01_spec_data_eval.md)) с идентификатором эксперимента из этой таблицы. Числа в реестр переносятся оттуда, не из памяти.
- После запуска исполнитель меняет «Статус» и заполняет «Результат»: метрика на каждом срезе, 95 % интервал или доля выигрышей в парном бутстрепе, время, одна строка вывода. Столбцы «Гипотеза» и «Ожидание» не редактируются задним числом.
- Статусы: `запланирован` → `выполнен` → `принят` / `отклонён` / `отложен`. Решение «принят/отклонён» выносится по правилу принятия из ТЗ 1; спорные случаи остаются `выполнен` до разбора.
- Срезы: `gold_raw` (208 строк), `gold_consensus` (138 текстов), `silver_cv`, `silver_fold0`, `challenge` (16 трудных примеров). Метрика по умолчанию — micro-F1.
- Новые эксперименты добавляются в конец своей группы со следующим номером.

Приоритет: 1 — нужно для рабочего решения; 2 — основной ожидаемый прирост; 3 — если останется время.
