# ТЗ 4. Единая функция предсказания, пакетный запуск, демо и замеры

Контекст — [00_overview.md](00_overview.md). Ментор просит простоту: без очередей, кэш-сервисов, нескольких сервисов и сложного интерфейса. Оценка времени на реализацию: 2,5 часа.

## Цель

Один процесс на Python, который: (1) отвечает на одно объявление в формате организаторов; (2) обрабатывает файл с объявлениями; (3) показывает это в простом веб-интерфейсе; (4) измеряет время и расход токенов.

## Единая функция

Вход: `description` (строка), `mcId` (целое), необязательный `title`. Выход — словарь строго вида:

```json
{"drafts": [{"mcId": 104, "title": "…", "text": "…"}]}
```

- Не больше одного элемента на категорию; `mcId` ∈ 102–106 и не равен входному; порядок по возрастанию `mcId`.
- Режимы (параметр и поле конфигурации): `classify` — `title` и `text` равны `null`; `full` — с генерацией; `fast` — классификация без LLM и шаблонные черновики.
- Пустое, слишком короткое или мусорное описание → `{"drafts": []}` без ошибок.
- Рядом с ответом функция умеет отдавать служебные сведения (вероятности, источник решения, цитаты, сработавшие проверки, время по шагам, токены) — отдельным объектом, не внутри `drafts`.
- Все настраиваемые значения (пороги, веса, пути к моделям, адрес LLM, размер контекста, режим) лежат в одном файле конфигурации.

## Пакетный запуск

Команда: входной файл (CSV, Parquet или JSONL со столбцами `description`, необязательными `title`, `mcId`, идентификатором) → выходной JSONL с идентификатором и ответом, плюс файл для отправки боту (идентификатор и список категорий; формат уточняется — вопрос 5 в [07_mentor_questions.md](07_mentor_questions.md), запись вынесена в одну маленькую функцию).

Порядок внутри пакета: сначала быстрые модели на всех строках батчами, затем LLM-проверяющий на неуверенных с несколькими одновременными запросами, затем генерация. Точные повторы текста обрабатываются один раз. Прогресс — в консоль. Сбой на одной строке не останавливает пакет: строка получает ответ быстрых моделей и пометку в журнале.

## Демо

Библиотека Gradio, одно окно, две вкладки:

1. **Одно объявление.** Поля: заголовок (необязательный), описание, исходная категория (по умолчанию 101), переключатель режима. Вывод: найденные категории с вероятностями и цитатами-основаниями; исходник и черновики рядом, бок о бок; сырой JSON ответа; время по шагам и число токенов.
2. **Файл.** Загрузка CSV → индикатор выполнения → таблица результатов и кнопка скачивания JSONL и CSV.

Требования: запуск одной командой; работает без интернета; при недоступной LLM интерфейс не падает, а показывает ответ режима `fast` с пометкой. Никакой авторизации, истории, базы данных.

## Замеры для защиты

Жюри просит назвать время и стоимость для итоговой конфигурации и отделить измеренное от оценок. Отдельная команда прогоняет фиксированную выборку (все 138 уникальных текстов теста) и пишет в `reports/benchmark.json`:

- время по шагам: нормализация, слои 1–4, LLM-проверяющий, генерация, проверки — медиана и 95-й перцентиль;
- объявлений в секунду в режимах `classify`, `fast`, `full`;
- долю объявлений, ушедших к LLM; среднее число вызовов LLM на объявление;
- токены на входе и выходе на один вызов проверяющего и на один черновик; токенов в секунду;
- пиковую видеопамять и оперативную память;
- то же при 1, 2 и 4 одновременных запросах к LLM (эксперимент S1).

Стоимость считается двумя способами и подписывается как оценка: электроэнергия (потребляемая мощность × время × тариф) и эквивалент по цене аренды GPU за час. Параметры расчёта — в конфигурации.

## Критерии приёмки

- Пример из постановки возвращает `drafts` с одним элементом `mcId` = 104.
- Проверка схемы ответа на всех строках `gold_raw` и на 16 трудных примерах: ни одного нарушения формата.
- Файл из 208 строк обрабатывается в режиме `classify` без ошибок; время записано.
- Демо открывается, обе вкладки работают, индикатор выполнения двигается.
- `reports/benchmark.json` создан и содержит все перечисленные показатели.
- В README есть раздел «Как запустить» из 5–7 команд.

## Требует проверки

- Помещаются ли LLM и энкодер в 8 GB одновременно; если нет — энкодер на CPU при выводе (эксперимент S2).
- Число одновременных запросов к LLM, дающее лучшую скорость без нехватки памяти.
- Формат файла для бота.

## Отклонения при реализации

- Реализованы единая функция (`predict.py`, режимы `classify`, `fast`, `full`) и пакетный запуск (`scripts/predict_batch.py`). Демо, замеры скорости и `reports/benchmark.json` — шаги 3 и 7, не сделаны.
- **Файл для бота** — JSONL со строками `{"id", "mcIds"}` (вопрос 5 к ментору без ответа); запись в одной функции `write_bot_file`.
- Пакетный запуск пока обрабатывает черновики последовательно, без одновременных запросов к LLM; дубли (одинаковые заголовок, описание и `mcId`) обрабатываются один раз.
- На публичных 208 строках режим `classify` отработал за 0,7 с (140 уникальных), ошибок нет.
- Проверки формата (`tests/test_format.py`) прогнаны на gold_raw и challenge в режимах `classify` и `fast`: нарушений нет.
