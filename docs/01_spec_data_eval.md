# ТЗ 1. Подготовка данных и инструмент оценки

Контекст — [00_overview.md](00_overview.md). Оценка времени на реализацию: 1,5 часа. Это первый шаг, от него зависят все остальные.

## Цель

1. Превратить исходные файлы в чистые таблицы с фиксированными разбиениями.
2. Дать один инструмент оценки, который считает micro-F1 так же, как организаторы, и умеет сравнивать два варианта решения с учётом шума малой выборки.

## Входы

- `dataset/public/public-train-annotated.jsonl` — поля `item_id`, `title`, `description`, `found_microcategories` (список объектов с `mcId` и `label`; пустой список — категорий нет).
- `dataset/public/public-test-dataset.parquet` — поля `title`, `description`, `categories` (список **названий**; идентификаторов нет). Соответствие: «Штукатурные работы» → 102, «Плиточные работы» → 103, «Сантехника» → 104, «Электрика» → 105, «Поклейка обоев и малярные работы» → 106. Других названий в файле нет (проверено).
- `data/challenge/seed_examples.jsonl` — 16 трудных примеров, написанных вручную (уже лежит в репозитории). Метки — наша трактовка правил, не эталон организаторов.

## Нормализация текста (общая для всех этапов)

Одна функция, которой пользуются обучение, вывод и демо:

1. Unicode NFKC; удалить невидимые символы (нулевой ширины, мягкий перенос).
2. **Подмена букв.** В словах, где смешаны кириллица и латиница, заменить латинские буквы-двойники на кириллические (a→а, c→с, e→е, o→о, p→р, x→х, y→у, k→к, m→м, t→т, b→в, h→н и заглавные). Слова целиком на латинице не трогать. Таких объявлений 2,4–2,9 %, и среди них доля пустых выше обычной.
3. Сохранить переводы строк (они несут структуру списков), схлопнуть повторные пробелы и пустые строки.
4. Эмодзи не удалять на этом шаге: маркеры списков нужны для разбиения на фрагменты. Модели, которым они мешают, убирают их сами.

Поле `text` = заголовок + перевод строки + описание. Заголовка может не быть (см. вопрос 1 в [07_mentor_questions.md](07_mentor_questions.md)) — тогда `text` = описание.

Ключ повтора `key` — нормализованное описание в нижнем регистре без всех символов, кроме букв и цифр.

## Выходы

Все — в `data/processed/` (в git не попадает, воспроизводится одной командой).

| Файл | Содержание |
| --- | --- |
| `silver.parquet` | Уникальные по `key` тексты трейна (ожидается 4 839). Поля: `item_id`, `title`, `description`, `text`, `key`, `cluster_id`, `fold`, `in_public_test`, `y102`…`y106`, `n_dups` |
| `gold_raw.parquet` | Все 208 строк теста как есть. Поля: `row_id`, `title`, `description`, `text`, `key`, `y102`…`y106` |
| `gold_consensus.parquet` | Уникальные по `key` тексты теста (ожидается 138). Метка категории — большинство голосов среди повторов. При равенстве голосов ячейка помечается как неопределённая (`m102`…`m106` = 0) и исключается из метрики. Поля те же плюс `n_dups`, `has_conflict`, маски |
| `challenge.parquet` | Трудные примеры в том же виде |

Правила:

- `cluster_id` — связные компоненты графа «косинусная близость TF-IDF по словам ≥ 0,8», построенного по объединению уникальных текстов трейна и теста. Ожидается около 3 000 кластеров по трейну.
- `fold` — 5 частей, целые кластеры в одной части (GroupKFold по `cluster_id`), фиксированное зерно.
- `in_public_test` = истина, если текст трейна попал в один кластер с каким-либо текстом теста. Такие тексты **исключаются из обучения всякий раз, когда модель оценивается на тесте** (иначе оценка завышена: 12 текстов теста есть в трейне с точностью до пробелов и знаков).
- Короткие и мусорные описания не удалять: они есть и в тесте, правильный ответ на них — пустой список.

## Инструмент оценки

Одна функция и команда командной строки. Вход: файл предсказаний (идентификатор строки и список `mcId`) и название среза. Действия:

1. Построить две бинарные матрицы «строки × [102, 103, 104, 105, 106]» и вызвать `sklearn.metrics.f1_score(y_true, y_pred, average="micro", zero_division=0)`. Никакой собственной формулы. Повторы `mcId` в предсказании схлопываются, значения вне 102–106 отбрасываются с предупреждением.
2. Дополнительно вывести: точность и полноту (micro), F1 по каждой категории, число лишних и пропущенных категорий, долю строк с пустым предсказанием и с пустым эталоном, число лишних категорий на строках с пустым эталоном.
3. **Доверительный интервал.** Бутстреп по группам повторов (`key`): 2 000 выборок групп с возвращением, перцентили 2,5 и 97,5.
4. **Сравнение двух вариантов.** Парный бутстреп на тех же выборках групп: распределение разности micro-F1, её 95 % интервал и доля выборок, где вариант Б лучше варианта А.
5. Дописать строку в `reports/runs.jsonl`: время, идентификатор эксперимента из [06_experiments.md](06_experiments.md), хеш конфигурации, срез, все метрики, время работы. Этот файл — источник цифр для реестра и слайдов.

Срезы:

| Срез | Данные | Зачем |
| --- | --- | --- |
| `gold_raw` | 208 строк | Сопоставимо с тем, как считали бы организаторы на публичном наборе |
| `gold_consensus` | 138 текстов, спорные ячейки исключены | Ближе к аккуратно размеченному приватному набору |
| `silver_cv` | Предсказания «вне своей части» по 5 частям | Чувствительный срез для дешёвых моделей |
| `silver_fold0` | Часть 0 как отложенная | Для дорогих моделей (энкодер, LLM на подвыборке) |
| `challenge` | 16+ трудных примеров | Отрицания, чужие услуги, сравнения; для слайда об уязвимостях |

Для режима без заголовка каждый срез можно посчитать с флагом «заголовок скрыт».

## Правило принятия изменений

Публичный тест не различает варианты с разницей меньше 0,03–0,05 (интервал бейзлайна 0,728–0,852). Поэтому изменение принимается, если одновременно:

1. на `gold_raw` доля выборок парного бутстрепа, где новое лучше, ≥ 0,85;
2. на `gold_consensus` micro-F1 не ниже прежнего;
3. на `silver_cv` или `silver_fold0` micro-F1 не упал больше чем на 0,005.

Если условия не выполнены, остаётся более простой вариант. Результат в любом случае записывается в реестр.

## Критерии приёмки

- Проверка метрики на примере из `task/hackathon-evaluation.md`: эталон {102, 104}, предсказание {102, 105} дают TP = 1, FP = 1, FN = 1.
- Число строк в таблицах совпадает с ожидаемым (4 839 / 208 / 138); расхождение — остановиться и разобраться.
- Сводка данных (доли пустых, частоты категорий, размеры кластеров) печатается и совпадает с таблицей в [00_overview.md](00_overview.md).
- Воспроизведены два ориентира и записаны в `reports/runs.jsonl`: правило по ключевым словам (ожидается около 0,81 на `gold_raw`) и «всегда пусто» (0,0).
- Повторный запуск даёт те же разбиения.

## Требует проверки

- Порог близости 0,8 для кластеров выбран по одному просмотру (при 0,6 — 2 600 кластеров, при 0,9 — 3 907).
- Пороги правила принятия (0,85 и 0,005) назначены экспертно.
- Список букв-двойников: проверить на объявлениях с подменой, что после нормализации слова находятся в словаре.
