# Обзор решения

Постановка и критерии — в `task/`. Здесь: что показали данные, какая архитектура выбрана и почему, что отброшено, риски.

## 1. Что показали данные

Все числа получены скриптами в `scratch/` (в git не попадают). «Трейн» — `public-train-annotated.jsonl` с автоматической разметкой, «тест» — `public-test-dataset.parquet` с ручной разметкой.

| Факт | Трейн | Тест |
| --- | --- | --- |
| Строк | 10 000 | 208 |
| Уникальных текстов (после удаления пробелов, знаков, регистра) | 4 839 | 138 |
| Строк без дополнительных категорий | 29,1 % (уникальные тексты: 27,7 %) | 51,0 % (уникальные тексты: 59,4 %) |
| Строк со всеми пятью категориями | 31,7 % | 9,1 % |
| Длина описания, символов: медиана / среднее / максимум | 2 196 / 2 324 / 5 564 | 1 343 / 1 627 / 4 480 |
| Описаний короче 60 символов | 342 строки | есть, в том числе мусор вроде «роаи» |
| Строк, где ≥ 20 слов смешивают кириллицу и латиницу (подмена букв) | 2,4 % | 2,9 % |
| Групп повторов с разными метками | 0 | 13 из 27 групп (в группах 97 строк) |

Дополнительно:

- **Трейн наполовину состоит из повторов.** 5 547 строк входят в группы точных повторов, самая большая группа — 76 строк. Близких повторов ещё больше: при объединении текстов с косинусной близостью ≥ 0,8 (TF-IDF по словам) 4 839 уникальных текстов сворачиваются в 3 003 кластера, крупнейший — 447 текстов. Часть текстов явно шаблонные. В 25 из 239 кластеров близких повторов метки различаются.
- **Тест шумный.** Согласие разметчиков между собой на повторах теста — micro-F1 0,727 (считалось попарно внутри групп повторов). Это оценка снизу: повторяются как раз спорные объявления.
- **Тест мало похож на трейн по текстам.** Только у 17 % уникальных текстов теста есть сосед в трейне с близостью > 0,8; медиана максимальной близости — 0,27. При этом 12 уникальных текстов теста (24 строки) есть в трейне с точностью до пробелов, знаков и регистра.
- **Автоматическая разметка трейна следует тому же правилу, что и ручная.** На 12 общих текстах метки совпали в 11 случаях (micro-F1 0,961, выборка мала). Правило ментора про пакетные услуги в разметке соблюдается: 79 уникальных текстов трейна с оговорками вида «только комплексный ремонт» — все без категорий; 46 текстов с «отдельные работы не берём» — 91 % без категорий. В тесте такие объявления тоже размечены пустыми.
- **Перечень работ внутри объявления «под ключ» обычно считается основанием для черновика.** Из 34 уникальных текстов теста, где ключевые слова находят три и более категории, 24 размечены непустыми единогласно, 5 полностью пусты (в них есть оговорки или услуги упомянуты вскользь), ещё в 5 разметчики разошлись: часть повторов пуста, часть нет.
- **Ключевые слова дают полноту, но не точность.** Простое правило по корням слов: micro-F1 0,918 относительно разметки трейна и 0,809 на тесте; на тесте полнота около 1,0 (кроме штукатурки — 0,71), точность 0,66–0,74.
- **Разведочный бейзлайн** (TF-IDF по символам и словам + логистическая регрессия на каждую категорию, обучение на уникальных текстах трейна без текстов теста): 0,949 на трейне при пятикратной перекрёстной проверке (оценка завышена близкими повторами), **0,792 на тесте** при пороге 0,5 (точность 0,709, полнота 0,898; 95 % доверительный интервал 0,728–0,852). Ошибок «лишняя категория» 109, «пропущенная» 30; 71 лишняя категория приходится на 22 строки, где эталон пуст. Сдвиг порога не помогает: 0,3 → 0,756; 0,7 → 0,770; 0,85 → 0,717.

Выводы, на которых стоит архитектура:

1. Разметке трейна можно доверять как обучающему сигналу, но оценку по ней нельзя считать честной без группировки близких повторов.
2. Главный источник ошибок — не калибровка, а смысл: объявление перечисляет работы, но (а) оговаривает «только комплексно», (б) упоминает их попутно («аккуратные стыки, розетки и выключатели» в объявлении о шумоизоляции), (в) описывает их как этапы единого ремонта одной фразой. Модель на n-граммах ставит таким объявлениям вероятность 0,9–0,99. Здесь нужен понимающий контекст компонент.
3. Публичный тест слишком мал и шумен, чтобы различать варианты с разницей меньше 0,03–0,05. Решения принимаются по парному бутстрепу и только при согласии с проверкой на трейне.
4. Доля пустых ответов в тесте вдвое выше, чем в трейне, но это в основном объявления без упоминаний работ вообще (75 из 106 пустых строк теста не содержат ни одного ключевого слова). Отдельная коррекция априорных вероятностей по умолчанию не нужна; проверяется экспериментом.

## 2. Архитектура

```
описание (+ заголовок, если есть)
        │
        ▼
[1] Нормализация текста ───────────────────────────────────────────┐
        │                                                          │
        ▼                                                          │
[2] Быстрые обученные модели (CPU / GPU, миллисекунды)             │
    2а. TF-IDF + логистическая регрессия        ┐                  │
    2б. дообученный русский энкодер (BERTA)     ├─► смесь вероятностей по 5 категориям
    2в. признаки контекста и оговорок           ┘   + порог + мера неуверенности
        │                                                          │
        ├── уверенный ответ (ожидаем 70–90 % объявлений) ──────────┤
        ▼                                                          │
[3] Локальная LLM-проверяющий — только для неуверенных объявлений  │
    T-lite-it-2.1 (8B, квантование Q4_K_M), вывод по JSON-схеме:   │
    для каждой категории статус и цитата-основание                 │
        │                                                          │
        ▼                                                          ▼
[4] Итоговый набор mcId (без исходной категории)  ──►  ответ без текстов: title/text = null
        │
        ▼
[5] Черновики — для каждой найденной категории:
    5а. отбор фрагментов исходника, относящихся к категории
    5б. генерация заголовка и текста той же локальной LLM по JSON-схеме
    5в. автоматическая проверка (числа, запрещённые формулировки, чужие услуги, новые слова)
    5г. одна перегенерация с замечаниями; если снова провал — шаблон из фрагментов исходника
        │
        ▼
{"drafts": [{"mcId", "title", "text"}]}
```

Свойства:

- **Слои независимы.** Шаг 2а один даёт рабочий ответ (0,79 на тесте). Каждый следующий слой включается флагом в конфигурации и может быть выброшен без переделки остального.
- **Обученная своя модель есть.** Шаги 2а–2в — модели, обученные нами на 10 тысячах примеров (перенос знаний большой разметочной модели в компактные). LLM — только для неуверенных случаев и текстов. Это ответ на риск «чистый промптинг».
- **Всё локально и без интернета.** Открытые веса (MIT, Apache-2.0), 8 GB видеопамяти достаточно: LLM занимает около 6,5 GB, энкодер при выводе может работать на CPU или загружаться по очереди с LLM.
- **Экономия обращений к LLM.** Классификация зовёт LLM только для неуверенных объявлений; генерация — только для найденных категорий; неизменная часть подсказки стоит в начале, чтобы сервер переиспользовал кэш префикса.
- **Отказоустойчивость на демо.** Если LLM недоступна, классификация работает на шаге 2, а черновики собираются шаблоном из фрагментов исходника.
- **«Генератор + проверяющий»** в части черновиков — схема, которую ментор назвал желательной.

Почему именно эти модели — в ТЗ: [02_spec_classification.md](02_spec_classification.md), [03_spec_drafts.md](03_spec_drafts.md).

## 3. Отброшенные варианты

| Вариант | Почему нет |
| --- | --- |
| Только LLM с подсказкой на каждое объявление | Риск оценки «модель не обучали»; в десятки раз медленнее; на 8 GB доступны только модели 8–9B. Остаётся как эксперимент-ориентир (C4). |
| Платные и зарубежные API | Жюри при равном качестве предпочитает локальное решение; требование проекта. |
| Дообучение LLM (LoRA) на разметке | Не укладывается в 24 часа и 8 GB вместе с остальным. |
| vLLM | Нет официальной поддержки Windows без WSL. |
| Энкодеры на 0,5 млрд параметров и больше (FRIDA, bge-m3, multilingual-e5-large) | Прирост на русских бенчмарках над BERTA — около 1 пункта, время обучения и вывода — в разы больше. |
| EmbeddingGemma, Qwen3-Embedding | EmbeddingGemma не работает в fp16, а bf16 на RTX 2080 Super нет; Qwen3-Embedding тяжёл для CPU. |
| SetFit | Рассчитан на десятки примеров на класс; при тысячах примеров обычное дообучение не хуже и проще. |
| Модель 12B (Gemma 3 12B, Vikhr-Nemo) | Файл 7–8 GB не помещается в 8 GB вместе с контекстом. |
| Очереди, кэш-сервисы, несколько сервисов, сложный интерфейс | Прямая просьба ментора не усложнять. |
| Отдельная NLI-модель как основной проверяющий | Работает на уровне предложений, точность на бенчмарках умеренная (около 74 %), лицензия одной из моделей не подтверждена. Оставлена как необязательный эксперимент (G5). |
| Коррекция априорных вероятностей (EM Саеренса) | Ошибки вызваны смыслом, а не сдвигом долей (см. вывод 4). Заменена простым экспериментом с порогами (C6). |

## 4. Риски и ограничения

| Риск | Что делаем |
| --- | --- |
| Публичный тест шумный и маленький: разница в 0,03 неразличима | Парный бутстреп по группам повторов; второй срез — трейн с группировкой близких повторов; правило принятия изменений в [01_spec_data_eval.md](01_spec_data_eval.md) |
| Приватный тест «сложнее»: больше отрицаний, чужих услуг, сравнений, которых в трейне мало | LLM-проверяющий; ручной набор трудных примеров `data/challenge/seed_examples.jsonl`; признаки оговорок |
| Правило для «перечня работ внутри ремонта под ключ» на приватном тесте может оказаться строже | Статусы LLM разделяют «перечислено как услуга» и «упомянуто как этап»; правило перевода статусов в ответ — один параметр; попытки отправки используются для выбора (см. раздел о попытках в [02_spec_classification.md](02_spec_classification.md)); вопрос к ментору |
| Во входе приватного теста может не быть заголовка | Обучение с отбрасыванием заголовка; оценка в обоих режимах |
| 8 GB видеопамяти: LLM и энкодер одновременно | Энкодер при выводе на CPU либо поочерёдная загрузка; замер в ТЗ сервиса |
| Маленькая LLM выдумывает факты в черновиках | Детерминированная проверка, перегенерация, шаблонный запасной вариант |
| Имена файлов моделей проверены только по страницам, не загрузкой; модели на этой машине не запускались | Первый шаг реализации — проверка окружения; запасные модели в [09_downloads.md](09_downloads.md) |
| Оценки скорости в документах — расчётные | Помечены словом «оценка»; заменяются замерами (ТЗ сервиса) |

Значения, выбранные без проверки, перечислены в конце каждого ТЗ в разделе «Требует проверки».
