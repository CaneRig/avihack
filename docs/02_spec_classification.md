# ТЗ 2. Определение целевых микрокатегорий

Контекст — [00_overview.md](00_overview.md). Данные и оценка — [01_spec_data_eval.md](01_spec_data_eval.md). Это 60 баллов из 100, главный этап.

## Цель

По тексту объявления вернуть подмножество {102, 103, 104, 105, 106} — категории, для которых исполнитель действительно предлагает услуги. Исходная категория из входа в ответ не попадает.

## Вход и выход этапа

- Вход: `description`, `mcId` исходной категории, необязательный `title`.
- Выход: для каждой из пяти категорий — вероятность, решение (да/нет), источник решения («быстрая модель» или «LLM») и, если звали LLM, статус и цитата-основание. Цитата потом используется в демо и при генерации черновика.

## Смысловое правило (едино для моделей, подсказок и разбора ошибок)

Категория ставится, если исполнитель предлагает соответствующие работы: они перечислены среди выполняемых либо прямо заявлены. Справочник работ — `task/microcategories-guide.md`. Категория **не** ставится, если:

- работы явно доступны только в составе комплексного ремонта («только комплексно», «отдельные работы не берём»);
- работа отрицается («электрику не делаем»), относится к другой стороне (подрядчик заказчика, магазин-партнёр), приведена для сравнения или в вакансии;
- упомянут предмет, а не работа («аккуратные стыки, розетки и выключатели» в объявлении о шумоизоляции);
- работы названы одной фразой как этапы единого ремонта («весь цикл — от демонтажа до монтажа сантехники и электрики») — принятое предположение, см. вопрос 3 в [07_mentor_questions.md](07_mentor_questions.md);
- есть только общая фраза «ремонт под ключ» без названий работ.

Границы категорий: шпаклёвка, грунтовка, шлифовка под покраску и обои → 106; штукатурка, выравнивание стен штукатуркой, откосы → 102; электрический тёплый пол → 105; водяной тёплый пол, радиаторы, отопление → 104; «укладка плитки под ключ» → 103.

## Слои

Каждый слой включается флагом в конфигурации. Слой 1 обязателен, остальные добавляются по результатам экспериментов.

### Слой 1. TF-IDF + логистическая регрессия (обязательный, CPU)

- Признаки: объединение TF-IDF по символьным n-граммам внутри слов (2–5) и по словам (1–2), сублинейная частота. Текст в нижнем регистре, «ё» → «е».
- Модель: отдельная логистическая регрессия на каждую из пяти категорий.
- Разведочный замер (эксперимент C1 его воспроизводит): C = 10, без взвешивания классов; 0,949 на `silver_cv` по точным повторам, **0,792 на `gold_raw`** при пороге 0,5. Полная перекрёстная проверка заняла около 3 минут на CPU.
- Перебор: C ∈ {1, 3, 10, 30}; символьные n-граммы (2–5) и (1–4); с заголовком и без.
- Артефакт небольшой, хранится в `artifacts/tfidf/` и коммитится.

### Слой 2. Дообученный энкодер (GPU, десятки минут)

Основной кандидат — **`sergeyzh/BERTA`**: лучшая из компактных моделей на русских задачах классификации (ruMTEB: классификация 69,8, многометочная 51,0 по карточке модели), около 0,1 млрд параметров, лицензия MIT, 0,51 GB, предел 512 токенов, размерность 768.

- Задача: пять независимых выходов с сигмоидой, функция потерь — бинарная перекрёстная энтропия.
- **Длинные тексты.** Медиана описания в трейне — 2 196 символов, это больше 512 токенов (точное распределение длин в токенах не измерено — измерить первым делом). Текст режется на окна до 512 токенов с перекрытием 64, не более 4 окон; оценка документа по категории — максимум по окнам; обучение сквозное на метках документа. Запасной упрощённый вариант — только первые 512 токенов.
- Заголовок случайно отбрасывается у 30 % примеров при обучении, чтобы модель работала и без него.
- Стартовые параметры: 3 эпохи, скорость обучения 3e-5 с линейным прогревом 10 %, смешанная точность fp16, 4 документа в батче с накоплением градиента до 16, префикс текста `categorize: `. Перебор: эпохи {2, 3, 5}, скорость обучения {2e-5, 3e-5, 5e-5}, сглаживание меток {0; 0,05}.
- Оценка — на `silver_fold0` (обучение на остальных частях) и на `gold_raw`/`gold_consensus`. Пятикратную проверку для энкодера не делаем: слишком долго. Итоговая модель обучается на всех уникальных текстах трейна.
- Расчёт времени (оценка, не замер): около 14 тысяч окон на эпоху, 5–15 минут на эпоху на RTX 2080 Super.
- Альтернативы (эксперимент C2b): `deepvk/USER2-base` — 149 млн параметров, контекст 8 192 токена, читает объявление целиком без окон (префикс `classification: `; не запрашивать FlashAttention 2 — на RTX 2080 его нет); `sergeyzh/rubert-mini-frida` — 32 млн параметров, для быстрого вывода на CPU.
- Веса сохраняются в `artifacts/encoder/` (в git не попадают).

### Слой 3. Признаки контекста и оговорок

Небольшой набор признаков на документ и на пару «документ, категория»:

- оговорки пакета: «только комплекс…», «исключительно комплексный», «отдельные (виды) работ(ы) не…», «не берём(ся) … отдельн…/мелк…» (в трейне такие тексты пусты в 91–100 % случаев);
- признаки отдельной услуги: «также отдельно», «как комплексно, так и отдельные виды работ», «частичный ремонт»;
- для категории: есть ли её ключевые корни в заголовке; в пункте списка; в одном предложении с отрицанием («не», «без», «кроме») или с маркером другой стороны («подрядчик», «партнёр», «магазин», «требуется»);
- длина текста, число пунктов списка, доля слов с подменой букв.

Два способа использования, сравниваются в эксперименте C7: (а) жёсткое правило «оговорка пакета → пустой ответ»; (б) признаки подаются в объединяющую модель слоя 4 и служат поводом позвать LLM.

### Слой 4. Объединение и порог

- Базовый вариант: взвешенное среднее вероятностей слоёв 1 и 2, вес слоя 1 ∈ {0,3; 0,5; 0,7}; один общий порог, старт 0,5.
- Варианты для экспериментов: пороги по категориям, стянутые к общему (C6); общая для всех категорий логистическая регрессия поверх вероятностей и признаков слоя 3, обученная на парах «документ, категория» (C10).
- **Неуверенность.** Объявление помечается неуверенным, если выполняется хотя бы одно: вероятность какой-либо категории ближе к порогу, чем на ширину полосы (старт 0,25); слои 1 и 2 дают разные решения по какой-либо категории; сработала оговорка слоя 3 при хотя бы одной категории выше порога. Ширина полосы подбирается так, чтобы неуверенных было 10–30 %.

### Слой 5. LLM-проверяющий для неуверенных объявлений

- Модель: **`t-tech/T-lite-it-2.1-GGUF`, файл `T-lite-it-2.1-Q4_K_M.gguf`** (5,03 GB, Apache-2.0, 8B, создана на основе Qwen3, без режима рассуждений; единственный кандидат с опубликованными русскими бенчмарками). На карте 12 GB — файл Q5_K_M (5,85 GB): по карточке модели квантование Q4_K_M заметно теряет на русской арене (71,7 против 78,6–78,9 у Q5). Запасные: `unsloth/Qwen3.5-9B-GGUF` (режим рассуждений отключить явно и проверить, что в ответе нет блока рассуждений) и `unsloth/gemma-4-E4B-it-GGUF`.
- Запуск: **Ollama** (уже установлен на машине), запросы к локальному адресу. Обязательные возможности клиента: вывод строго по JSON-схеме, явный размер контекста, температура 0, фиксированное зерно, несколько одновременных запросов, чтение из ответа числа токенов и длительностей. Клиент делается так, чтобы адрес и формат можно было переключить на `llama-server` из llama.cpp (он тоже принимает JSON-схему и параллельные слоты).
- Стартовые настройки: контекст 4 096 токенов на запрос, 2 одновременных запроса. Расчёт памяти (оценка): 5,0 GB веса + около 1,2 GB кэш контекста + служебное ≈ 6,5 GB.
- **Что спрашиваем.** Только о категориях-кандидатах: вероятность слоя 4 выше 0,05 или найден ключевой корень; остальные считаются отсутствующими без запроса. Для каждой категории-кандидата модель возвращает сначала короткую цитату из объявления (до 15 слов), затем статус:
  - `offered` — работа перечислена среди выполняемых или прямо предлагается;
  - `stage_mention` — названа одной фразой как этап единого ремонта;
  - `package_only` — явно только в составе комплексного ремонта;
  - `not_offered` — отрицание, чужая услуга, сравнение, вакансия, упоминание предмета;
  - `absent` — не упомянута.
- **Подсказка** (хранится отдельным файлом): роль; смысловое правило из этого ТЗ; определения пяти категорий одной-двумя строками с границами; 5–6 коротких примеров на разные статусы; затем объявление. Неизменная часть стоит первой, чтобы сервер переиспользовал кэш префикса. Примеры в подсказке не должны совпадать с текстами из `challenge` и теста.
- **Правило перевода статусов в ответ**: `offered` → да, остальные → нет. Трактовка `stage_mention` — отдельный параметр (эксперимент C13).
- Для неуверенного объявления решение LLM заменяет решение слоя 4 по категориям-кандидатам (вариант: только по категориям внутри полосы неуверенности — эксперимент C5).
- Расчёт скорости (оценка): 4–8 секунд на объявление в одном потоке.

LLM на всех объявлениях без быстрых моделей — эксперимент-ориентир C4, не итоговая конфигурация.

### Слой 6. Итог

Набор категорий с решением «да», минус исходная `mcId`, по возрастанию. Если исходная категория не 101, ответ всё равно строится только из 102–106; категорию 101 как целевую решение не предлагает (нет данных для обучения) — ограничение записано в вопросах к ментору.

## Работа с шумом разметки

- Обучение только на уникальных текстах; близкие повторы не разносятся по разным частям.
- Эксперимент C9: ячейки «документ, категория», где предсказание вне своей части уверенно противоречит метке (вероятность < 0,1 при метке 1 или > 0,9 при метке 0), исключаются из функции потерь либо переразмечаются LLM-проверяющим. Библиотека cleanlab не обязательна: ранжирования по уверенности достаточно.
- Эксперимент C8: добавить в обучение тексты публичного теста с метками-консенсусом (ментор разрешил). Оценка — перекрёстной проверкой по группам внутри теста.

## Приватный набор и попытки отправки

Попыток 2–3, ошибки не показывают. Порядок:

1. Прогон только классификации (без генерации). Целевое время — не больше 30 минут на весь набор вместе с LLM-проверяющим; если неуверенных слишком много, сузить полосу.
2. Проверки без эталона до отправки: доля пустых ответов (ориентиры: 51–59 % в публичном тесте, 28 % в трейне), частоты категорий, доля неуверенных, число строк и формат. Резкое отличие — повод остановиться, а не отправлять.
3. Попытка 1 — лучшая проверенная конфигурация.
4. Попытка 2 — конфигурация, отличающаяся по самому неопределённому решению (кандидаты: без LLM-проверяющего против с ним; трактовка `stage_mention`). Выбор кандидата — по реестру экспериментов.
5. Попытка 3 — лучшая из двух с одной небольшой правкой либо не используется.

Предсказания каждой попытки и конфигурация сохраняются в `reports/submissions/`.

## Критерии приёмки

- Слой 1 воспроизводит 0,78–0,80 на `gold_raw` и записан в `reports/runs.jsonl`.
- Каждый включённый в итог слой прошёл правило принятия из ТЗ 1.
- Итоговая конфигурация: micro-F1 на `gold_raw` не ниже 0,85 и не меньше 13 из 16 трудных примеров с точным совпадением набора (оба числа — цель, назначенная без проверки).
- Режим без заголовка теряет не больше 0,01 на `gold_raw`.
- Измерены и записаны: время обучения каждого слоя; скорость вывода слоёв 1–4 (объявлений в секунду на CPU и GPU); доля неуверенных; время и число токенов на один вызов LLM.
- Одна команда обучает всё и одна команда строит предсказания для файла.

## Оценка времени на реализацию

Слой 1 — 0,5 ч; слой 2 — 2 ч вместе с обучением; слои 3–4 — 1 ч; слой 5 — 2 ч; эксперименты и подбор — 1,5 ч. Слои 2 и 5 независимы и могут делаться параллельно.

## Требует проверки

- Длины текстов в токенах и число окон на документ; хватает ли 4 окон.
- Все стартовые параметры слоя 2 и оценки времени обучения.
- Порог 0,5, ширина полосы 0,25, порог кандидата 0,05, веса смеси.
- Префикс `categorize: ` при дообучении BERTA (карточка рекомендует его для эмбеддингов; для дообучения влияние неизвестно).
- Размер контекста и число одновременных запросов LLM на 8 GB; фактическая скорость.
- Потеря качества T-lite при Q4_K_M на нашей задаче; сравнение с запасными моделями (C4).
- Предположение о `stage_mention`.
